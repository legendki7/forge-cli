# دليل استخدام ForgeKi

[English](./README.md) | **العربية**

[مستودع ForgeKi](../../README.md) · [الأمان](../../SECURITY.md) ·
[المساهمة](../../CONTRIBUTING.md)

ForgeKi أداة تطوير مفتوحة المصدر تساعدك على إنشاء مشاريع البرمجيات وتهيئتها وفحصها وتجهيزها من
دون تركيب كل ملف إعداد يدوياً. يمكنك استخدام تطبيق **ForgeKi Desktop** بواجهته الرسومية للعمل
المرئي الكامل، أو استخدام واجهة الأوامر `forge` عندما تفضّل الطرفية. لا يحتاج المبتدئ إلى تعلّم CLI
حتى يستفيد من تطبيق Desktop.

> **تنبيه Beta:** يستعد ForgeKi لأول إصدار تجريبي عام. قد تتغير المخرجات وواجهات API ومخططات
> Plugin قبل الإصدار المستقر. Windows هو المنصة الوحيدة التي جرى التحقق من تطبيق Desktop عليها.
> كما أن مزودي Marketplace والتحديثات للإنتاج غير مهيّئين حالياً.

## ما الذي يستطيع ForgeKi فعله؟

يستطيع ForgeKi:

- إنشاء مشاريع TypeScript حتمية من خمسة قوالب Next.js محلية؛
- تركيب مشاريع Next.js أو React/Vite أو Express في Visual Stack Builder؛
- تصميم Workspace متعددة الخدمات وتوليدها؛
- فحص مشروع موجود من دون تشغيل شفرته؛
- إضافة إعدادات Docker وGitHub Actions من دون استبدال ملفات موجودة؛
- التحقق من Plugin تصريحية مقيّدة وتثبيتها؛
- قراءة Marketplace بعيد وموقّع عند تهيئة مزود رسمي؛
- تصميم مخططات متغيرات بيئات Local وStaging وProduction؛
- توليد ومعاينة إعدادات Docker وKubernetes والمواقع الثابتة وخوادم Node؛
- فحص أدوات المطور وحالة الأمان والتحديثات والنشاط المحلي؛ و
- تصدير تشخيصات آمنة للخصوصية أو تشغيل `forge doctor`.

لا يستضيف ForgeKi التطبيقات ولا ينشرها، ولا يشغّل عناقيد Kubernetes، ولا يوفّر بنية سحابية، ولا
يثبّت اعتماديات المشروع، ولا يشغّل شفرة Marketplace عشوائية، ولا يستخدم الذكاء الاصطناعي.

## المتطلبات والتثبيت

### تشغيل ForgeKi Desktop

يتضمن تطبيق ForgeKi Desktop المثبّت بيئة التشغيل اللازمة لفتحه. لا يحتاج المستخدم العادي إلى Rust
أو Cargo أو pnpm أو تثبيت Node.js منفصل لمجرد تشغيل التطبيق. Windows هو منصة Desktop الأصلية
الوحيدة التي تحقّق منها المشروع حالياً. لا يحدد المستودع إصدار Windows أدنى، ولا يدّعي التحقق من
تطبيق Desktop على macOS أو Linux.

### تطوير المشاريع المولّدة

للمشروع الذي تولّده متطلباته الخاصة. تحتاج غالبية المشاريع إلى إصدار Node.js مدعوم وإلى مدير الحزم
الذي اخترته: pnpm أو npm أو Yarn أو Bun. تحتاج Git فقط إن أردت تهيئة مستودع، وتحتاج Docker فقط
لبناء صور الحاويات أو تشغيلها. تفحص صفحة **Developer Tools** هذه الأدوات ولا تثبّتها.

تدعم ForgeKi CLI إصدارات Node.js 20 و22 و24. يستخدم المساهمون في المستودع pnpm 9 أو أحدث أيضاً؛
راجع [CONTRIBUTING.md](../../CONTRIBUTING.md) لإعداد بيئة المساهمة.

### التثبيت على Windows

مسار التثبيت المقصود هو:

```text
مستودع GitHub
→ Releases
→ أحدث إصدار ForgeKi مناسب
→ تنزيل ملف إعداد ForgeKi
→ تشغيل المثبّت
→ فتح ForgeKi
```

**قد لا تتوفر إصدارات مثبّت عامة بعد. تحقّق من صفحة
[Releases](https://github.com/legendki7/forge-cli/releases) في المستودع.** لا تنزّل مثبّتاً من مصدر
غير مرتبط بالمستودع الرسمي.

مثبّتات Beta الحالية غير موقّعة بـ Authenticode، لذلك قد يعرض Windows SmartScreen تحذير ناشر غير
معروف أو تحذير سمعة. تأكد أن الملف جاء من المستودع الرسمي وراجع قيمة checksum المنشورة إن وجدت. لا
تعطّل حماية Windows بصورة عامة.

## التشغيل الأول

يفتح ForgeKi على صفحة **Home**. يتضمن الشريط الجانبي: Home وCreate Project وTemplates وStack
Builder وWorkspace Builder وEnvironments وDeployment وScan Project وMarketplace وSecurity
وDeveloper Tools وActivity وAbout وSettings. تعرض Home إجراءات سريعة والمشاريع ومساحات العمل
والنشاط المخزّن محلياً. ويمكن طي الشريط الجانبي.

يتبع المظهر إعداد النظام افتراضياً، ويمكن اختيار System أو Light أو Dark من Settings. وضع المستخدم
الافتراضي هو Beginner. لا توجد شاشة تسجيل دخول أو حساب سحابي أو طلب موافقة على تحليلات أو telemetry.

## وضع Beginner ووضع Advanced

يعرض **Beginner Mode** الخيارات بلغة أبسط ويخفي البيانات الثانوية. يناسبك إذا كنت تعرف النتيجة التي
تريدها ولا تعرف كل الحزم الداخلية.

يعرض **Advanced Mode** تفاصيل آمنة إضافية، مثل إصدارات الاعتماديات والسكربتات ومخططات البيئة وملكية
الملفات والمعاينة الدقيقة. لا يخفف التحقق أو الأذونات أو حدود الأمان. ولا يختار قاعدة بيانات أو ORM
تلقائياً.

غيّر الوضع من **Settings → Project defaults → User mode**.

## إنشاء مشروعك الأول

افتح **Create Project** أو اختر **Create a project** من Home. لا يكتب المعالج ملفات قبل التأكيد.

1. **Project** — اكتب اسماً صغير الأحرف ومتوافقاً مع npm، واختر المجلد الأب، ثم راجع المسار النهائي.
2. **Template** — اختر واحداً من قوالب Next.js الخمسة المدمجة.
3. **Tooling** — اختر pnpm أو npm أو Yarn أو Bun، ثم فعّل اختيارياً **Initialize Git repository**
   و**Add Docker configuration** و**Add GitHub Actions CI**.
4. **Review** — راجع المسار والقالب ومدير الحزم والأدوات الاختيارية وقائمة الملفات المتوقعة.
5. **Create** — اختر **Confirm and create**. يتحقق ForgeKi من الطلب، وينشئ الملفات عبر منطقة تجهيز
   آمنة، ويعرض حالة كل عملية.

ينشئ ForgeKi ملفات المصدر والإعداد فقط ولا يثبّت الاعتماديات. بعد النجاح استخدم **Open project
folder** أو **Copy project path**، ثم نفّذ أوامر التثبيت والتطوير المعروضة بنفسك. يرفض ForgeKi وجهة
تحتوي ملفات بدلاً من استبدالها.

## القوالب

تستخدم القوالب المدمجة Next.js App Router وTypeScript وCSS محلياً ومحتوى حتمياً، ولا تعتمد على أصول
بعيدة وقت التشغيل. إنها بدايات قابلة للتطوير وليست تطبيقات إنتاج مكتملة.

| القالب                   | الاستخدام الأنسب                | الأساس المضمّن                                     |
| ------------------------ | ------------------------------- | -------------------------------------------------- |
| **Blank Next.js App**    | بداية نظيفة                     | صفحة App Router بسيطة وCSS محلي                    |
| **Next.js Dashboard**    | لوحات الإدارة والأدوات الداخلية | تنقل متجاوب ومؤشرات وجدول تجريبي                   |
| **Next.js Blog**         | المواقع المعتمدة على المحتوى    | تدوينات محلية ومسارات ومعلومات وصفية وخطوط متجاوبة |
| **Next.js Portfolio**    | عرض الأعمال والمشاريع           | مقدمة ومشاريع ومهارات وموضع معلومات اتصال          |
| **Next.js Landing Page** | صفحات المنتجات والخدمات         | Hero وشبكة ميزات ودعوة لاتخاذ إجراء وتذييل         |

تتيح صفحة **Templates** البحث والتصفية قبل فتح معالج الإنشاء.

## منشئ Stack المرئي

الـ **Stack** هو مجموعة تقنيات وأدوات تطبيق واحد. يتيح Stack Builder اختيارها بصرياً، ويتحقق من
توافقها، ثم يجهز الملفات التي تمثل اختياراتك.

يتضمن الكتالوج المدمج:

- أطر العمل: Next.js وReact + Vite وExpress؛
- اللغة وبيئة التشغيل: TypeScript وNode.js؛
- التنسيق: Plain CSS وTailwind CSS؛
- البيانات: PostgreSQL أو SQLite مع Prisma أو Drizzle؛
- الاختبارات: Vitest وPlaywright؛ و
- الأدوات: Git وDocker وGitHub Actions.

اختر المكونات من الكتالوج، ثم افحص شجرة البنية وتفاصيل المكوّن. يميّز ForgeKi المتطلبات الإلزامية،
ويشرح الخيارات غير المدعومة، ويمنع التعارضات مثل قاعدتي بيانات أو Prisma بلا قاعدة بيانات أو أدوات
خادم مع React/Vite. تعرض المراجعة شجرة الملفات ومحتواها من الخطة نفسها التي ستُستخدم للتوليد. يمكنك
تحميل Preset أو حفظ Preset محلي محدود. لا تُستبدل الملفات الموجودة ولا تُثبّت الاعتماديات.

## منشئ Workspace

يصف Project أو Stack تطبيقاً واحداً. أما **Workspace** فتصف monorepo محلياً يحتوي خدمات متعددة
وعلاقاتها، مثل:

```text
Web App
   ↓ HTTP
API
   ↓ DATABASE
PostgreSQL
```

يتضمن كتالوج الخدمات Next.js وReact + Vite وExpress API وPostgreSQL وSQLite وRedis ومكتبة
TypeScript مشتركة (**Shared TypeScript Library**). أنواع الاتصال المدعومة هي:

- `HTTP`: تطبيق ويب يستدعي API؛
- `DATABASE`: Express أو Next.js القادر على العمل كخادم يستخدم PostgreSQL أو SQLite؛
- `CACHE`: Express أو Next.js القادر على العمل كخادم يستخدم Redis؛ و
- `SHARED_PACKAGE`: خدمة ويب أو API تستخدم مكتبة TypeScript المشتركة.

تخطط اللوحة المنافذ ومخططات متغيرات البيئة بصورة حتمية. لا يمكن React/Vite الاتصال مباشرة بقاعدة
بيانات أو Redis. تُرفض الاتصالات المكررة أو الذاتية أو ذات الأطراف المفقودة أو غير المدعومة. راجع
البنية والملفات الدقيقة وخطة Docker Compose وCI ومصفوفة البيئة قبل التوليد. ينشئ ForgeKi ملف
`forgeki.workspace.json` ومجلدات الخدمات، لكنه لا يثبّت الاعتماديات ولا يشغّل الحاويات ولا ينشر شيئاً.

## فاحص المشروع

افتح **Scan Project**، واختر مجلد مشروع، ثم اضغط **Scan project**. الفحص للقراءة فقط ويعتمد على
ملفات الإعداد: يقرأ ForgeKi ملفات معروفة ومحدودة مثل `package.json` وlockfiles ومسارات إعداد معروفة.
ولا يشغّل سكربتات المشروع أو شفرة مجهولة.

قد يتعرف على اسم المشروع، وإطار Next.js أو React/Vite أو Express أو Node عام، وTypeScript أو
JavaScript، ومدير الحزم، والسكربتات، والاعتماديات، والملفات المعروفة، وDocker، وGitHub Actions، وحالة
Plugin المدمجة، ومكونات Stack المدعومة، والتحذيرات، وأدلة الفحص التصريحية. يمكن أن تكون النتيجة
**Detected** أو **Likely detected** أو **Conflicting** أو غير معروفة عندما لا تكفي الأدلة.

## التوصيات

التوصيات حتمية وتعتمد على قواعد. **لا يرسل ForgeKi مشروعك إلى خدمة ذكاء اصطناعي.** من أمثلتها
غياب إعداد Docker، أو غياب GitHub Actions CI، أو عدم وجود سكربت test/lint/typecheck معروف، أو وجود
أكثر من lockfile، أو تأكيد وجود إعداد TypeScript. أنت من يقرر تطبيق التوصية المدعومة، وتُحفظ
التوصيات التي تتجاهلها محلياً.

## Plugin

توسّع Plugin الملفات والإعدادات التي يمكن لـ ForgeKi توليدها:

- **Built-in plugins**: تطبيقات TypeScript موثوقة تأتي مع ForgeKi. المدمج حالياً Docker وGitHub
  Actions.
- **Community plugins**: حزم تصريحية مقيّدة تأتي من أمثلة مضمّنة أو استيراد محلي أو Marketplace
  بعيد مهيّأ.
- **Developer plugins**: مشاريع تصريحية محلية تنشئها وتتحقق منها قبل مشاركتها.

Community Plugin بيانات وليست برامج. لا تستطيع تنفيذ JavaScript أو أوامر shell أو lifecycle scripts
أو ملفات تنفيذية أو عمليات عشوائية أو عمليات نشر أو واجهات شبكة ForgeKi. تغطي أذوناتها المعلنة
أعمالاً محدودة مثل توليد ملفات آمنة، وإضافة اعتماديات registry أو سكربتات، وتعريف مخططات البيئة،
وإضافة مكونات Stack وقواعد فحص محافظة. يجب أن يطابق كل إسهام إذناً معلناً وأن ينجح في التحقق.

للتفاصيل المتقدمة راجع [نظرة عامة على Plugin](../plugins/overview.md) و[مرجع
manifest](../plugins/manifest.md) و[نموذج الأمان](../plugins/security.md).

## Marketplace

تحتوي صفحة **Marketplace** تبويبات **Installed** و**Built-in** و**Community** و**Developer**.
يمكنك فحص التفاصيل والأطر والفئات والأذونات والسلامة وحالة التثبيت والتوافق. تبقى Plugin المدمجة
متاحة دون اتصال. أما أمثلة المجتمع المضمّنة فهي معاينات حتى تؤكد تثبيتها.

تشمل شارات الناشر **ForgeKi** و**Verified Publisher** و**Community Publisher** و**Revoked**
و**Unknown** عند انطباقها. التوقيع الصحيح يثبت المفتاح الذي وقّع Plugin، لكنه لا يعني تلقائياً أن
ForgeKi يوصي بها. يبقى فحص الأمان التصريحي إلزامياً.

تُتحقق بيانات Marketplace البعيدة قبل أن تستبدل الذاكرة المحلية، ويجري البحث في الفهرس المحلي
الموثّق. يحافظ فشل التحديث على cache سبق التحقق منه، لذلك قد تبقى المعلومات متاحة دون اتصال. تُعطل
Plugin المثبتة إذا أُلغيت أو فسدت، فلا تستخدم في توليد جديد.

مزود Marketplace البعيد للإنتاج غير مهيأ حالياً. يعتمد توفره على المزود الذي يهيئه إصدار ForgeKi
رسمي، وتعرض الصفحة هذه الحقيقة بدلاً من استعمال خدمة غير موثوقة. راجع [أمان
Marketplace](../marketplace/overview.md).

## تثبيت Plugin

1. افتح Marketplace واختر عنصراً من Built-in أو Community أو Developer.
2. اختر **View details** وافحص الناشر والأطر المدعومة.
3. راجع الأذونات والإسهامات المطلوبة.
4. للعناصر البعيدة، تأكد من نجاح فحص التوقيع وdigest والإلغاء والتوافق.
5. راجع التغييرات الدقيقة وتقرير الأمان.
6. أكد التثبيت أو تطبيق العنصر المدمج.
7. يعيد ForgeKi التحقق، ويجهز الحزمة في quarantine، ولا يثبّت إلا البيانات التصريحية.

يجب تمكين Plugin المجتمع المحلية في Settings. ويتطلب تطبيق عنصر مدمج اختيار مشروع الهدف. تُحفظ
الملفات الموجودة. إزالة Plugin تحذف بيانات تثبيتها، ولا تحذف الملفات التي سبق أن ولّدتها داخل مشروع.

## تحديث Plugin

تعرض مراجعة التحديث الإصدار المثبّت والمتاح وحالة الناشر والسلامة وأي أذونات جديدة. تتطلب زيادة
الأذونات تأكيداً منفصلاً وصريحاً. يتحقق ForgeKi من التحديث المختار ويثبته ذرياً، ولا يحدّث Plugin
بصمت عندما قد تتغير المخرجات أو الأذونات. ويُحظر ناشر أو تحديث ملغى.

## ملفات تعريف البيئة

يصمم ForgeKi ملفات **Local** و**Staging** و**Production**. تعريف المتغير يصف الاسم والغرض والمالك
وكونه إلزامياً أو سرياً والبيئات التي تستخدمه. أما قيمة السر فهي كلمة المرور أو token أو credential
الحقيقية. يخزن ForgeKi التعريفات ولا يخزن أسرار الإنتاج.

تعرض صفحة **Environments** بطاقات الملفات والملكية وشارات Public/Secret وRequired/Optional وبنية
Workspace والمقارنات وحالة drift. تحتوي ملفات `.env*.example` المولّدة أمثلة عامة آمنة أو قيماً سرية
فارغة. لا ينشئ ForgeKi ملف `.env` حقيقياً.

## Deployment

ForgeKi **يولّد إعدادات النشر**، لكنه لا ينشر إلى السحابة، ولا يصادق مع مزود، ولا يشغّل `kubectl`،
ولا يبدأ الخدمات، ولا يبني الصور أو يدفعها، ولا ينشئ بنية تحتية.

الأهداف المدعومة هي **Docker Compose** و**Generic Docker** و**Kubernetes** و**Static Export**
و**Node Server**. يعتمد التوافق على المشروع أو Workspace المفحوصة. سير العمل هو:

| معرّف الهدف      | الأساس المولّد                                  |
| ---------------- | ----------------------------------------------- |
| `docker-compose` | إعداد Docker متعدد الخدمات                      |
| `generic-docker` | Dockerfiles موجهة للإنتاج                       |
| `kubernetes`     | ملفات manifest أولية للمراجعة والاستخدام اليدوي |
| `static-export`  | بيانات وصفية لاستضافة واجهة ثابتة               |
| `node-server`    | تعليمات عامة لبيئة تشغيل Node                   |

1. اختيار أو فحص مشروع/Workspace؛
2. اختيار Local أو Staging أو Production وهدف متوافق؛
3. مراجعة أخطاء الجاهزية والتحذيرات؛
4. معاينة الملفات الحتمية بدقة؛
5. اختيار مجلد تصدير منفصل والتأكيد؛ و
6. التصدير فقط عندما تكون المسارات آمنة ولا توجد تعارضات ملفات.

يستطيع ملف `forgeki.deployment.json` الاختياري تسجيل بصمة البنية وhash للملفات المولّدة من دون مسارات
أو أسماء مستخدمين أو توقيتات أو أسرار. يبلّغ الفحص اللاحق عن الملفات المطابقة أو المعدّلة أو المفقودة
أو المجهولة، ولا تُستبدل الملفات المعدّلة. راجع [دليل Deployment](../deployment/overview.md).

## Docker

عند تمكين Docker لمشروع واحد، يولّد ForgeKi ملف `Dockerfile` و`.dockerignore` مناسبين للإطار. يتجاوز
الملفات الموجودة بدلاً من استبدالها. ويمكن لـ Workspace متعددة الخدمات توليد إعداد Docker Compose
جذري وملفات Docker لكل خدمة.

لا يبدأ التوليد Docker ولا يبني أو يدفع image ولا يصادق مع registry. راجع المعاينة ثم شغّل Docker
بنفسك بعد فحص الملفات.

## GitHub Actions

يولّد تمكين GitHub Actions ملف `.github/workflows/ci.yml`. يكتشف ForgeKi سكربتات المشروع المتاحة
ويدرج خطوات lint وtypecheck وtest وbuild المدعومة عندما تكون موجودة. يشغّل CI الخاص بـ Workspace
سكربتات التحقق منها. هذا workflow للتكامل المستمر فقط، ولا يولّد عملية نشر سحابية.

## أدوات المطور

اختر **Check tools** في صفحة Developer Tools لتشغيل أوامر إصدار ثابتة ومسموح بها لـ Node.js وnpm
وpnpm وYarn وBun وGit وDocker وVS Code وRust وCargo. يُعد Node.js ضرورياً لتطوير JavaScript، أما
البقية فاختيارية بحسب عملك.

- **Installed/Available**: نجح أمر الإصدار الثابت.
- **Not detected/Missing**: لم يوجد الأمر.
- **Unavailable**: انتهت مهلة الفحص.
- **Check failed**: أعاد الأمر خطأً.

الفحص محافظ. على Windows قد تظهر بعض أدوات مديري الحزم القائمة على command wrapper كأنها غير
مكتشفة رغم أنها تعمل من shell آخر؛ تحقق بأمر الأداة قبل إعادة تثبيتها. لا يثبّت ForgeKi أداة مفقودة.

## سجل النشاط

تخزن صفحة **Activity** ما يصل إلى 200 عملية ForgeKi حديثة على هذا الجهاز. قد تشمل إنشاء المشاريع
وفحصها، وتوليد Stack/Workspace، وعمليات Plugin، وتحديث Marketplace، وفحص التحديثات، وفحص/تصدير
Deployment، والتحذيرات، والإخفاقات. يمكنك التصفية أو المسح. لا يوجد سجل سحابي أو مزامنة حساب أو رفع
telemetry.

## الإعدادات

تشمل Settings حالياً:

- **اللغة:** `English` أو `العربية`؛ تتحول واجهة Desktop فورًا وتستخدم تخطيط RTL مع
  العربية. يُحفظ هذا الإعداد محليًا، وتبقى مخرجات CLI بالإنجليزية في هذا الإصدار؛
- **Appearance:** مظهر System/Light/Dark وطي الشريط الجانبي؛
- **Project defaults:** مدير الحزم والوجهة وGit وDocker وGitHub Actions ووضع Beginner/Advanced؛
- **Stack Builder defaults:** الإطار والتنسيق والاختبار وتذكّر آخر Stack وتأكيد المكونات المطلوبة؛
- **Deployment defaults:** البيئة والهدف وعدد نسخ Kubernetes وملف Docker للإنتاج والبيانات الوصفية
  والخيارات المتقدمة؛
- **Plugin platform:** Marketplace البعيد والفحص التلقائي وPlugin المحلية وأمثلة التجربة؛
- **Secure updates:** قناة Stable/Beta والفحص التلقائي؛ و
- **Application:** مسح المشاريع الحديثة/النشاط أو إعادة الإعدادات.

لا يوجد unsafe mode. لا يمكن تعطيل التحقق من Plugin أو السلامة أو الأذونات المقيّدة. ولا يستخدم فحص
التحديث إلا مزوداً موثوقاً مهيأً، ولا يكون التثبيت صامتاً.

## الأمان

يقوم نموذج أمان ForgeKi العملي على:

- توليد محلي أولاً وحتمي؛
- مجلدات يختارها المستخدم ومسارات نسبية آمنة وقراءات محدودة؛
- إنشاء حصري وعدم الاستبدال افتراضياً؛
- إعادة حساب الخطط المراجعة قبل التنفيذ؛
- Community Plugin تصريحية بمخططات وأذونات مغلقة؛
- فحص التوقيع وdigest والإلغاء وquarantine والسلامة؛
- تنزيلات محدودة وشبكة مزودين مقيّدة؛
- عدم تشغيل شفرة Plugin أو shell أو telemetry أو AI؛ و
- عدم استخدام credentials نشر أو تنفيذ إجراءات سحابية تلقائية.

للإبلاغ عن ثغرة وقراءة نموذج التهديد الكامل، راجع [SECURITY.md](../../SECURITY.md). لا تنشر تفاصيل
الثغرة في Issue عام قبل اتباع السياسة.

## الخصوصية

تبقى عمليات ForgeKi الأساسية على جهازك. تقتصر طلبات Marketplace على بيانات ثابتة موقّعة والحزمة
التي تختارها صراحة. لا يرسل ForgeKi أسماء المشاريع/Workspace أو المصدر أو المسارات أو الاعتماديات أو
قيم البيئة أو الأسرار أو هوية npm أو GitHub أو أحداث التثبيت أو معرّف عميل دائم. ولا يحتوي telemetry
أو analytics أو tracking pixels أو صور Plugin بعيدة.

خدمات Marketplace والتحديثات البعيدة للإنتاج غير مهيأة حالياً. إذا هُيئت خدمات رسمية لاحقاً، تبقى
طلباتها ضمن البروتوكول وحدود الخصوصية الموثقة. راجع [خصوصية Marketplace](../marketplace/privacy.md).

## عن ForgeKi

تعرض صفحة **About** إصدار Desktop وقناة Stable/Beta وترخيص MIT والمستودع وحالة الثقة الحالية
لـMarketplace والتحديث وتنبيه Beta. يعرض زر **Check for updates** حالة المزود المهيأ. وتوفر الصفحة
مسار التشخيص التالي.

## التشخيصات

في **About → Export Diagnostics** اختر أولاً **Preview diagnostics**. يحتوي تقرير JSON المسموح على
المنتج/الإصدار/القناة واسم نظام التشغيل العام وإصدار مخطط الإعداد وحالات أدوات المطور وإصداراتها
المنقحة ومعرّفات Plugin وإصدارها/سلامتها وحالات المزود وما يصل إلى 20 نوع تحذير/فشل حديثاً مع الوقت.
اختر **Save JSON** بعد مراجعة التقرير فقط.

تستبعد التشخيصات عمداً أسماء المشاريع ومساراتها ومسارات المنزل وأسماء المستخدمين والمصدر وقيم البيئة
والأسرار وtokens وكلمات المرور وcredentials والإعدادات الخاصة. راجع كل ملف بنفسك قبل إرفاقه بـIssue.

المكافئ في CLI هو:

```bash
forge doctor
forge doctor --json
```

يعرض تشخيص CLI إصدار ForgeKi وNode وسياسة runtime المدعومة وتوفر الأدوات الأساسية ومدير الحزم
المفضل وحالات المزود والتحذيرات. ولا يفحص أو يرفع المصدر.

## مقدمة CLI

لا تحتاج إلى CLI لاستخدام ForgeKi Desktop. تفيد CLI للأوامر القابلة للتكرار والعمل في الطرفية
والأتمتة. شغّل `forge --help` أو `forge <command> --help` قبل تغيير مشروع. اسم الحزمة المقصود حالياً
هو `@forgecli7/cli`، ويجب تأكيد توفرها العام على npm من المستودع الرسمي قبل تثبيتها.

## أوامر CLI الأساسية

| الأمر                                     | الغرض                                     |
| ----------------------------------------- | ----------------------------------------- |
| `forge --help`                            | عرض الأوامر والأمثلة                      |
| `forge --version`                         | عرض إصدار CLI المثبّت                     |
| `forge doctor` / `forge doctor --json`    | فحص runtime والأدوات والمزودين            |
| `forge check`                             | فحص المشروع الحالي دون تغييره             |
| `forge create`                            | فتح معالج الإنشاء التفاعلي                |
| `forge create <name> [options]`           | توليد مشروع بخيارات أو Preset             |
| `forge add [docker\|github-actions]`      | إضافة ميزة مدمجة بأمان                    |
| `forge stacks list`                       | عرض إعدادات Stack الستة                   |
| `forge stacks show <preset>`              | فحص إعداد Stack                           |
| `forge workspaces presets`                | عرض إعدادات Workspace الخمسة              |
| `forge workspaces show <preset>`          | فحص إعداد Workspace                       |
| `forge workspace create [name] [options]` | توليد Workspace متعددة الخدمات            |
| `forge workspace check [directory]`       | فحص Workspace دون تغييرها                 |
| `forge environments list`                 | عرض Local وStaging وProduction            |
| `forge deployment targets [directory]`    | عرض أهداف النشر كلها أو المتوافقة         |
| `forge deployment check [directory]`      | فحص الجاهزية دون كتابة                    |
| `forge deployment plan [directory]`       | معاينة خطة النشر الدقيقة                  |
| `forge deployment export [directory]`     | التصدير بعد مراجعة وتأكيد صريحين          |
| `forge plugins list`                      | عرض Plugin المدمجة والمضمّنة والمثبّتة    |
| `forge marketplace status`                | عرض حالة المزود وcache والثقة والإلغاء    |
| `forge update check`                      | فحص بيانات الإصدار الموقعة دون تحديث ذاتي |

استخدم `--env local|staging|production` و
`--target docker|docker-compose|kubernetes|static|node` مع أوامر deployment. راجع `--help` لمعرفة
خيارات التأكيد والوجهة قبل التصدير.

## أمثلة CLI

### إنشاء مشروع

```bash
forge create my-app --preset nextjs-starter
forge create api --framework express --database postgres --orm drizzle --testing vitest --docker
```

احذف الاسم أو أضف `--interactive` لاستخدام الأسئلة. الإعداد الصريح الافتراضي هو pnpm وGit، وتكون
Docker وGitHub Actions معطلة حتى تطلبها.

### إضافة Docker

```bash
cd my-app
forge add docker
```

يمكن تشغيله ثانية بأمان؛ تُحفظ ملفات `Dockerfile` و`.dockerignore` الموجودة.

### فحص مشروع

```bash
cd my-app
forge check
```

### فحص إعدادات Stack

```bash
forge stacks list
forge stacks show nextjs-fullstack
```

### تشخيص ForgeKi

```bash
forge doctor
forge doctor --json
```

### العمل مع Workspace

```bash
forge workspaces presets
forge workspace create my-workspace --preset full-stack-postgres --destination . --docker
forge workspace check ./my-workspace
```

## التنقل بلوحة المفاتيح

يستخدم ForgeKi حالياً تنقل نظام التشغيل/المتصفح القياسي، ولا يعرّف اختصارات خاصة بالمنتج. استخدم
`Tab` و`Shift+Tab` للتنقل، والأسهم داخل القوائم ومجموعات radio، و`Space` لخانات الاختيار والأزرار،
و`Enter` لتفعيل العنصر المحدد. تُظهر حلقات التركيز العنصر النشط، وتحمل الحوارات والإجراءات تسميات
لتقنيات المساعدة. لا تعتمد على اختصار غير موثق.

## استكشاف المشكلات

### لا يفتح ForgeKi

أعد تشغيل التطبيق، وتأكد أنه من المستودع الرسمي، وافحص هل عزل برنامج الحماية الملف. أعد التثبيت من
إصدار رسمي إن توفر. إذا تكررت المشكلة، أرفق تشخيصات آمنة في Issue.

### تحذير Windows SmartScreen

قد تكون مثبّتات Beta الحالية غير موقّعة. تحقق من المصدر الرسمي وchecksum. استخدم مسار المراجعة في
Windows فقط إذا وثقت بالملف نفسه؛ لا تعطّل SmartScreen عالمياً.

### لم يُكتشف Node.js أو Git أو Docker أو مدير الحزم

نفّذ أمر الإصدار في طرفية جديدة مثل `node --version` أو `git --version` أو `docker --version`. ثبّت
الأداة أو أصلحها من مصدرها الرسمي ثم أعد فتح ForgeKi. لا تحتاج Docker لمجرد توليد إعداداته. وقد تعطي
command wrappers في Windows نتيجة محافظة، لذلك تحقق يدوياً قبل إعادة التثبيت.

### فشل إنشاء المشروع

ارجع إلى Review، وتحقق من الاسم والوجهة وإذن الكتابة. لا يثبّت ForgeKi الاعتماديات، لذلك تظهر أخطاء
تثبيتها لاحقاً في طرفيتك لا أثناء الإنشاء.

### مجلد الوجهة غير فارغ

اختر اسماً جديداً أو وجهة فارغة. يرفض ForgeKi الدمج مع مجلد موجود أو استبداله.

### Marketplace غير متاح أو دون اتصال

افتح Settings وتأكد من تمكين Remote Marketplace، ثم اقرأ التنبيه. مزود الإنتاج غير مهيأ حالياً.
عند وجود مزود يمكن أن يبقى cache متحقق منه متاحاً دون اتصال، ولا يستبدله فشل التحديث ببيانات مجهولة.

### رُفضت Plugin أو أُلغيت

افتح **View details** واقرأ رسائل الأمان والسلامة والأذونات والناشر. أصلح manifest محلياً بدلاً من
تجاوز التحقق. تُعطل Plugin الملغاة أو الفاسدة ولا تُستخدم لتوليد جديد.

### خدمة التحديث غير مهيأة

هذه حالة الإنتاج المتوقعة حالياً. لا ينتقل ForgeKi إلى endpoint غير رسمي، ولا تحدّث CLI نفسها. افحص
صفحة Releases الرسمية يدوياً.

### مشكلة توليد GitHub Actions

تأكد أن `.github/workflows/ci.yml` غير موجود وأن `package.json` يحتوي السكربتات المتوقعة. تُحفظ
workflow الموجودة. راجع الملف المولّد قبل دفعه إلى GitHub.

### مشكلة توليد Docker

تأكد أن الإطار معروف وأن `Dockerfile` و`.dockerignore` غير موجودين. لا يحتاج التوليد إلى Docker
daemon؛ أما بناء النتيجة أو تشغيلها فيحتاج إليه.

### خطأ إذن أو مسار

اختر مجلداً محلياً عادياً تملكه. تجنب مجلدات النظام المحمية والروابط الرمزية والمسارات التي تهرب من
المجلد الأب. يرفض ForgeKi المسارات غير الآمنة عمداً.

### الإبلاغ عن خطأ قابل للتكرار

افتح [GitHub Issues](https://github.com/legendki7/forge-cli/issues) وقدّم إصدار ForgeKi ونظام التشغيل
وخطوات التكرار والنتيجة المتوقعة والفعلية وتشخيصات آمنة راجعتها. لا ترسل أسراراً أو credentials أو
شفرة خاصة أو قيم بيئة خاصة.

## الأسئلة الشائعة

### هل ForgeKi مجاني؟

نعم. ForgeKi مفتوح المصدر وفق [ترخيص MIT](../../LICENSE).

### هل يستخدم ForgeKi الذكاء الاصطناعي؟

لا. التوليد والفحص والتوصيات والتحقق والتوافق حتمية ومحلية، ولا يرسل ForgeKi المشاريع إلى خدمة AI.

### هل يرفع ForgeKi شفرة مشروعي؟

لا. تبقى عمليات المشروع وWorkspace الأساسية محلية، ولا تتضمن طلبات Marketplace المصدر أو بيانات
هوية المشروع.

### هل يستطيع ForgeKi نشر تطبيقي؟

لا. يولّد ForgeKi إعدادات نشر قابلة للمراجعة. أنت مسؤول عن credentials والبنية والأوامر والتنفيذ.

### هل تستطيع Community Plugin تشغيل شفرة على جهازي؟

لا. هي بيانات تصريحية متحقق منها ولا تشغّل JavaScript أو shell أو binaries أو عمليات عشوائية. أما
Docker وGitHub Actions المدمجان فهما شفرة موثوقة تأتي مع ForgeKi وتستخدم توليداً آمناً بلا استبدال.

### هل أحتاج Node.js لفتح ForgeKi Desktop؟

لا عند استخدام Desktop المثبّت؛ تأتي بيئة worker المطلوبة مضمّنة. غالباً تحتاج Node.js لتطوير مشروع
JavaScript/TypeScript الذي ينشئه ForgeKi، كما تحتاجه CLI.

### هل يدعم ForgeKi macOS أو Linux؟

صُممت CLI المبنية على Node.js للعمل في بيئات Node المدعومة، لكن التحقق من إصدار Desktop الأصلي
مقتصر حالياً على Windows. لا يدّعي المشروع التحقق من بناء Desktop على macOS أو Linux.

### لماذا يحذر Windows من ForgeKi؟

مثبّتات Beta الحالية غير موقّعة بـ Authenticode، لذلك قد لا تتوفر سمعة SmartScreen. استخدم ملفات
المستودع الرسمي فقط وراجع checksums إن توفرت.

### من أين تُنزّل التحديثات؟

لا يوجد مزود تحديث إنتاج مهيأ حالياً. يجب أن تستخدم الإصدارات الرسمية المستقبلية بيانات موقّعة
وحزماً متحققاً منها مع تأكيد المستخدم. لا يثبّت ForgeKi تحديثاً بصمت، ولا تحدّث CLI نفسها.
